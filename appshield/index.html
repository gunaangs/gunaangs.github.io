Part I: Privacy Policy

1. Overview & Privacy Commitment

Welcome to AppShield: Mobile Security (“we”, “our”, or “the App”), developed and published by Angs Corp.

AppShield is a standalone, local-first mobile security scanner, privacy auditor, and system optimization utility. It is designed to inspect installed applications, calculate heuristic risk scores, audit dangerous sensor and system permissions, detect sideloaded APKs, boost system memory, and clean residual junk files. AppShield is architected strictly as a 100% on-device, zero-telemetry utility.

CRITICAL NOTICE — ZERO DEVELOPER BACKUPS & 100% LOCAL STORAGE ARCHITECTURE:

AppShield is a 100% offline, local storage-based application. There are NO cloud backups, automated server backups, remote databases, or cloud sync services provided by Angs Corp or the developer. All audit reports, scanned package metrics, whitelists, and preferences reside strictly and exclusively on your physical device hardware.

100% USER RESPONSIBILITY FOR DATA LEAKS, THEFT & DEVICE SECURITY:

Because Angs Corp does not possess, transmit, or back up your data on any server, Angs Corp bears ZERO responsibility or liability for any data leak, data breach, unauthorized access, or data theft. If any data loss, breach, or theft occurs because your device is compromised, hacked, infected with third-party malware/spyware, physically lost, stolen, rooted, jailbroken, unlocked, or left unattended, it is 100% the responsibility of the user side and NOT the developer side. You are solely responsible for securing your physical device.

Zero-Server Architecture: All package scanning, heuristic risk calculation, memory optimization, and permission audits are executed locally on your device hardware. Your list of installed applications and device telemetry are never transmitted to, inspected by, or stored on Angs Corp servers or any external third-party cloud.

2. Data Handled & Device Permissions

AppShield only accesses information strictly required to perform on-device security scans, privacy audits, and device maintenance upon your initiation:

Permission / API How It Is Used Data Storage / Transmission
Package Visibility (QUERY_ALL_PACKAGES) Allows AppShield to inspect installed packages and metadata (permissions requested, installer source, certificates, target SDK) for heuristic risk scoring and the Privacy Matrix. Never uploaded. Processed strictly in volatile memory and local on-device SQLite database for trend reporting.
Memory Management (KILL_BACKGROUND_PROCESSES) Used locally by the RAM Booster to terminate idle background tasks and reclaim device memory upon your tap. Never uploaded. Operates purely locally via Android OS process APIs.
App Uninstallation (REQUEST_DELETE_PACKAGES) Triggers the standard Android uninstallation confirmation dialog for flagged risky or sideloaded apps. Never uploaded. Native system intent.
Notifications (POST_NOTIFICATIONS) Delivers on-device notifications for scheduled security audits and high-risk detection alerts. Operates completely on-device via Android WorkManager without remote push tracking.
Storage Inspection & Preview Scans storage directories locally to identify residual junk, empty folders, and large media with an interactive file preview modal. Processed strictly on-device. Zero file contents or documents are read or transmitted off-device.
Advertising Identifier (AD_ID) Used by Google Mobile Ads SDK (AdMob) to deliver ads and prevent fraudulent impressions subject to user consent. Handled by Google Mobile Ads SDK in accordance with Google's Privacy Policy and UMP consent framework.

3. Third-Party Services & Ad Isolation

AppShield processes security scans fully offline. The only third-party service integrated into the App is Google Mobile Ads:

  • Google Mobile Ads (AdMob): Used to serve in-app advertisements.
  • Consent Management: We implement Google's User Messaging Platform (UMP) to obtain explicit consent for personalized ads in compliance with GDPR, CCPA, and global privacy frameworks.
  • Strict Isolation: The Google Mobile Ads SDK runs in an isolated sandbox and has zero access to your installed application inventory, risk scores, sensor privacy matrix, or audit reports.

4. User Rights & Data Erasure

Because AppShield stores audit reports and preferences only on your device, you have complete sovereignty over all data:

  • In-App Reset: Clear scan history, trusted apps whitelists, and cached metrics directly in AppShield Settings.
  • System Settings: Clear application cache and storage via Android System Settings.
  • Uninstallation: Uninstalling AppShield permanently destroys all locally generated scan caches, settings, and database records.
